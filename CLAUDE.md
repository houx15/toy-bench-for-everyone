# Personal AI Scorer Kit

Open-source skill set that turns a person's own AI usage history into a private benchmark, runs it on any new model, and reports which model should do which job for them. Built first for the author (Yuxin) as a personal tool; a validation study may make it research later.

Full spec (human-readable): https://claude.ai/code/artifact/c1fbba84-7f55-46b2-b0c5-3f66dfcb9407 — this file is the self-contained version for coding.

## Core idea

Public leaderboards measure an average user who doesn't exist. This kit measures *my* tasks.

Two phases:

**Setup (once, in the user's most-used AI app):**
1. Install — user gives the generic kit to the AI app holding their memory/history.
2. Mine — app scans past sessions, proposes task buckets covering real usage.
3. Interview — app discusses with user: confirm buckets, pick tasks, supply gold answers / anchors, set weights.
4. Freeze — saved as the user's personal kit (versioned, plain portable format).

**Run (every new model release):**
1. Hand off — user sends their kit to any capable AI, names models to compare.
2. Fan out — parallel runs, task × model × 3 repeats.
3. Grade — automatic checks first, rubric judging for the rest, user spot-checks a sample.
4. Report — scored report, a job persona per model, updated team roster.

## Design principles

- **Portable**: plain folder usable as an AI skill AND runnable from a terminal. Never locked to one app.
- **User-owned, open source**: nothing collected centrally.
- **Grounded in real use**: tasks come from the user's history, not synthetic puzzles.
- **Measurement defined up front**: every task type has a recipe written before any model runs.
- **Fun but honest**: enjoyable report, but every headline links to task-level evidence.

## Building tests from usage

- **Coverage sampling**: embed past sessions, cluster, pick representatives so few tasks cover the most distinct kinds of use.
- **Frequency weighting**: sample for coverage, but weight scores by usage share.
- **Bucket types** (author's own usage as the worked example):

| Bucket | Example uses | How to test |
|---|---|---|
| Model-dependent | Paper reading, literature review, paper rewrite, brainstorming | Core of the kit: personal tasks + recipes |
| Public-benchmark covered | Coding, end-to-end AI product dev | Reuse public scores + 3–5 tasks from user's own repo |
| Product/tool-dependent | Daily AI digest, document management | Manual app check, or leave out |
| High stakes | Health management, training planning | Score safety/appropriateness, not cleverness |

- **Discriminative items**: over repeated runs, use item response theory (cf. tinyBenchmarks) to keep items that separate models.

## Measurement recipes (the main contribution)

Each recipe = rubric + anchor examples + automatic checks + calibration procedure.

| Task type | Checkable parts | Method |
|---|---|---|
| Paper digest | Coverage of 10–15 user-written gold claims; answers to prewritten "why"/"limitations" questions; quality of raised questions (1–3 scale w/ anchors); hallucinated claims | Gold claims + anchored scale |
| Brainstorming | Novelty = embedding distance from a baseline idea pool generated by several models; diversity = # distinct clusters; usefulness = user rating | Embeddings + user rating |
| UI design | Auto: contrast, phone-width layout, console errors; aesthetics: hierarchy, spacing, consistency | Screenshot + blind pairwise vs reference |
| Architecture | Coverage of hidden spec requirements; rewrite needed after a change request | Checklist + change-request test |
| Report writing | Claim-level fact check vs sources; structure/argument rubric | Fact-check + rubric anchored on one excellent example |
| Paper rewrite | Meaning preserved, voice kept, target improvements made | Claim diff + blind pairwise |
| Coding | Tests pass on real past commits | Checkout pre-fix commit, request change, run tests |

Rules:
- **Judge calibration**: before trusting an AI judge on a recipe, it grades ~20 outputs the user also graded; compute Cohen's κ (categorical) or correlation (numeric). Low agreement → refine rubric / add anchors.
- **No self-grading**: the model under test never grades its own outputs.
- **Preference ≠ capability**: correctness graded blind and objectively; preference via blind pairwise with length/formatting recorded. User sets per-task weighting.

## Report

- **Job persona** per model, nearest role to its strength profile, with an evidence line. Starting roles: Research Analyst, Senior Engineer, Creative Strategist, Editor, Generalist.
- **Team roster** across tested models = the routing table.
- Layout: persona card → fit weighted by user's usage mix → radar (one axis per bucket, new model vs current favorite) → use for / don't use for → highlight reel (best/worst outputs) → cost, speed, consistency → roster.

## Repo layout

```
SKILL.md              # instructions for an AI app: setup interview (incl. mining), run, report
recipes/              # one YAML per task type: criteria, anchors, judge prompt, thresholds
scorer_kit/           # Python package, CLI entry point `scorer` (cli.py)
  schemas.py          # pydantic models for every file
  kit.py              # load + validate a kit folder
  graders/            # automatic checks, judge prompt filling/parsing, scoring, mocks
  runner/             # backends (openrouter, bailian, app handoff, mock) + resumable fan-out
  calibration.py      # κ / weighted κ / correlation + blind grading sheets
  report/             # HTML template, aggregation, personas
examples/demo-kit/    # complete fictional kit used by tests and the offline demo
my-kit/               # produced by setup; personal, gitignored
  profile.yaml        # buckets, usage shares, current favorite
  tasks/              # inputs, gold answers (flat yaml or one folder per task)
  calibration/        # blind sheets + judge agreement history
results/<run>/        # gitignored: run.yaml, outputs/, grades/, handoff/, report.html
```

Run `uv run pytest` for tests; `uv run scorer run examples/demo-kit -m mock:a -m mock:b -j mock:j` for an offline end-to-end check.

- Task file: id, bucket, recipe, input (prompt + attachments), gold material, weight.
- Recipe file: criteria, scale + anchors, automatic checks, judge prompt, calibration threshold.
- Optional context pack: text export of user memory, given identically to every model.

## Decisions (2026-10-13)

- **Two run modes.** API mode via `openrouter:` (OPENROUTER_API_KEY) or `bailian:` (DASHSCOPE_API_KEY), user's choice per model. App mode (`app:<label>`) for people without API access: the runner writes paste-able prompt files + `HANDOFF.md`, the user pastes replies into `.response.md` files, `scorer resume` picks them up. Judges can be app models too. `mock:` runs everything offline.
- **No chat-history export.** Mining happens inside the user's AI app, driven by the setup prompt in SKILL.md. Task resources (papers, drafts) are collected from the history during setup.
- **Attachments are text only** (.md/.txt), converted once at setup, so every model gets identical input.
- **Brainstorming novelty baseline** = the task's static baseline ideas + other models' ideas in the same run (leave-one-out), so a model is never compared against its own ideas. Similarity is character-trigram cosine (offline, free); neural embeddings could come later.
- **Provisional defaults** for open questions below: judge threshold κ ≥ 0.6 (per recipe, editable); fixed roles in `scorer_kit/report/personas.py`.
